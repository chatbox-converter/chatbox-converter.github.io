# VRCOSC ↔ neutral model mapping

Source of truth for the file format: `.references/notes/vrcosc-format.md` (VRCOSC `2026.807.0`,
official modules `2026.501.1`); community packages: `.references/notes/ecosystem-plugins.md` Part A
(Bluscream/VRCOSC-Modules `2026.0926.2`, branch `stable`).

Files: `chatbox.json` (the ChatBox timeline, always `"version": 1` first), `modules/<FullID>.json`
(per-module `enabled` + non-default `settings`), `configuration/settings.json` (global settings).
Both are read with `lossless-json` so .NET tick values (`> 2^53`) survive as `bigint`
(`vjson.ts`); integers that fit a double become plain numbers.

## Canonical placeholder ↔ module variable

Reverse index order = built-ins, official modules (catalog order), community modules (older
Bluscream modules, then the `2026.0926.2` ones, then Yeusepe's). **Segment-level module
preference** (`compile.ts` `planModules`): per segment, a greedy set cover picks the module that
provides the most of the segment's placeholders, then the next one for what is left; ties go to the
segment's heart-rate `provider`, then official modules, then catalog order. Stateless modules never
take part. Hence a plain `♥ {heartrate}` uses Pulsoid, `{heartrate} ({heartrate_min}-{heartrate_max})`
takes everything from Heartrate Stats; `▶ {artist} - {title}` uses the official Media module,
`{artist} ♪ {lyrics}` Linux Media (and then its real `playicon`/`progresspercent` variables);
`{weather_temp} {weather_condition}` the official Weather module, anything with
`weather_feels_like`/`weather_wind`/`weather_emoji` Open-Meteo (MagicChatbox Parity is the last
resort for weather and only wins `vrc_instance_capacity`, `vr_reprojection`, `vr_dropped_frames`).
`weather_temp`/`weather_feels_like` follow `temperatureUnit` (`tempc`/`tempf`, `feelslikec`/`feelslikef`);
`timer` uses the built-in countdown for `custom` segments and the Stopwatch module otherwise.

Every canonical placeholder now has a source in a module that registers states (asserted in
`bluscream.test.ts`). A placeholder that still cannot be resolved is reported with
`collector.unsupported`, its token removed with separator tidy; a segment that loses all its
placeholders is dropped.

**Stateless modules.** `Clip.calculateValidClipState` only accepts a compound state whose keys equal
the set of running linked modules, and states exist only for modules that register them. A clip
linked to `vrchatapi`, `desktopfpsmodule` or `shazamosc` therefore never renders, so serialize
refuses to use them (`stateless-module` warning, only reachable when nothing else provides the
placeholder) even though the catalog lists their variables for parsing. Every community module a
clip links produces a `community-module` info naming the package and repository to install.

## Serialize: the single combined clip

1. Enabled segments are compiled into one line (`\n` or `output.separator`, plus prefix/suffix).
   Placeholders become `{n}` in first-use order; the same variable with identical options is
   reused. `options` are `{}` when all default, otherwise the full class + base set (as VRCOSC
   writes them). Progress and text variables are therefore always written in full.
2. `linked_modules` = modules in first-use order (+ `afkdetectionmodule` when AFK is enabled).
3. States = cartesian product of **every** state of every linked module (the catalog's `states`
   keys, main state first): a linked module in a state with no matching compound state makes
   VRCOSC hide the whole clip, so `offline`, `notininstance`, `unavailable`, `idle`, `noruntime` …
   all get a state. Per combination a segment whose module left its main state uses
   (`serialize.ts` `variantTemplate`): media `paused`/`stopped` (also SpotiOSC `Paused_*`) →
   `pausedTemplate`/`stoppedTemplate` (other `Playing_*` states render like the main one; a non-media
   segment such as `♪ {lyrics}` hides); heart-rate `disconnected` → `disconnectedTemplate`;
   stopwatch `stopped` → hidden, `paused` → unchanged; AFK → the status segment shows the AFK
   template (or it replaces everything); Linux Audio FX `playing`/`idle` → unchanged (`idle` still
   holds the voice preset); MagicChatbox Parity → unchanged unless the segment uses
   `vrc_instance_capacity`/`vrc_master`; Status module `idle` and every other non-main state →
   segment hidden (`''`). Combinations whose format ends up empty are skipped. Dictionary keys are
   emitted in `linked_modules` order (VRCOSC matches them with an order-sensitive `SequenceEqual`).
   Every state has `enabled: true`, `show_typing: false`, `use_minimal_background` =
   `output.minimalBackground`. **Guard:** above 512 combinations only the all-main state plus the
   states where exactly one module leaves its main state are written (`too-many-states` warning).
4. One clip on layer 0 `[0, 60)` named after the profile, always (no per-status timeline clips).
5. **Status module rule:** with more than one status, `statusCycle.enabled`, or any non-empty
   `group`, `{status}` compiles to `bluscream.vrcosc.modules.statusmodule` `text` (options `{}`),
   the module is linked (`default` main, `idle` hides the status segment) and
   `modules/bluscream.vrcosc.modules.statusmodule.json` gets `settings.statuses`
   `[{text, group, cycle: useInCycle}]` (active status first), `cycle: true`, `interval`
   (`max(1, round(intervalSeconds))`, omitted when 30), `random: true`, `prefixicon: false` — only
   non-default keys, VRCOSC style — plus a `status-module` info naming the package. A single
   ungrouped status without cycling keeps the built-in `text` variable (works without extra modules).
6. `modules/<FullID>.json` for every linked module: `{version: 1, enabled: true, settings: {…non-default…}, parameters: {}}`
   (DateTime `timezone`, Weather / Open-Meteo `location`, Status module list).
7. Diagnostics: `import-instructions` (ChatBox → Import, required packages), `community-module`,
   `status-module`, `unsupported-feature` per placeholder, `stateless-module`, `too-many-states`,
   `visibility`, `afk-timeout`.

## VRCOSC → VRCOSC round trip (`merge.ts`)

When `extras.vrcosc` holds the imported document and every profile segment still belongs to a
mapped state, the imported document is rewritten in place:

- a state whose segments are unchanged (same `template` + `options` signature, all enabled) is
  copied verbatim;
- an edited state is recompiled from its segments (joined with `\n`); if the new variable set
  equals the old one, the original variable order and options are kept and `{n}` renumbered, and
  only the options the model expresses are overlaid (a timer `datetime` is kept when it denotes
  the same millisecond, so ticks survive bit-for-bit);
- the `{status}` state is always recompiled from the active status text, or from the Status
  module `text` variable when the original state used it, in which case
  `modules/…statusmodule.json` is re-emitted with the list/cycle settings refreshed from the profile;
- all-disabled segments set `enabled: false` on their state; the AFK state follows `afk.enabled`;
- clips, timing, layers, events, unmodelled states and module files are emitted untouched.

Adding or re-creating segments falls back to the fresh strategy (`structure-changed` info).

## Losses per direction

VRCOSC → model: events, `show_typing`, scroll/case/truncate options except the media title,
`float_format`/`mode`/`symbol_list`, bool `when_true`/`when_false`, timeline timing and layers
(kept as notes + extras), disabled clips/states, compound states with several non-main modules,
Counter/VRCX/HomeAssistant dynamic variables (kept as `{module:variable}` literals), module
settings other than timezone/location/enabled, `OutgoingEndpoint`/`ChatBoxSendInterval` are read
but never written back.

Model → VRCOSC: desktop/VR visibility, AFK timeout, transient media,
`HardwareOptions.temperatureUnit` (VRCOSC reports °C only), `WindowOptions`, `VrBatteryOptions`,
`WeatherOptions` coordinates/IP mode/interval, `showTimezone`, `smoothing`; the Status module's
`disabledgroups`/`overridegroup`/icons are left at their defaults; Heartrate Stats gets
`provider: 1` for `hyperate` (Pulsoid is its default, Bluetooth has no counterpart there). Newtonsoft writes floats such as `8.0`; lossless-json re-emits `8`,
which VRCOSC reads identically.
